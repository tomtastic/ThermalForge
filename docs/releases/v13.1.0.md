# ThermalForge 13.1.0

ThermalForge 13.1.0 brings the `nextgen` architecture to the app and CLI: one control
backend owns profiles, rules, calibration and normal fan writes, while an independent
recovery service restores Apple control after a failed controller has exited.

## Changes

- Protected client sessions make control ownership explicit. CLI `set`, `max` and
  `watch` run in the foreground; `--takeover` revokes the GUI session and leaves the
  app observing. An observing client cannot reset another client's fans.
- Recovery persists permission before manual writes, monitors completed backend
  work, and verifies handback before allowing new control. Status requests cannot
  keep a stalled controller's protection alive.
- Calibration is an exclusive backend job. Cancellation stops workloads before
  handback, and interrupted or partial results are not saved.
- Authoritative profiles and rules are stored per authenticated console user;
  machine calibration is stored separately for each lid state. Validated legacy
  imports preserve the original files.
- Target writes allow bounded acknowledgement delay while checking cancellation
  and manual mode. Each target is written once while waiting; unlocking and all
  acknowledgements share an eight-second budget. Persistent failure pauses control
  and reports the requested and observed values.
- Local control failures require explicit retry, preventing automatic write/restore
  loops. Eligible profile recovery after backend communication failures is retained.
- The menu distinguishes applying, paused, idle and acknowledged control. Profile
  selection follows live ownership, and selecting the same profile can retry a
  paused session. Explicit Apple control selects Silent.
- Installer fixes handle absent launchd jobs, asynchronous service startup and
  repair of an unreachable older recovery service without bypassing handback.

## Install or upgrade

Requires Apple Silicon and macOS 14 or later. Download `ThermalForge.app.zip`, quit
the existing app, and replace `/Applications/ThermalForge.app`. Install the matching
backend and recovery service before reopening the app:

```sh
sudo "/Applications/ThermalForge.app/Contents/Resources/thermalforge" install
```

Confirm the app and `thermalforge --version` report `13.1.0`, then select a profile.
After a CLI takeover or explicit `thermalforge auto`, select a profile explicitly
to resume GUI control. Ctrl-C releases a foreground CLI session to Apple control.

The CLI-only archive is `thermalforge-cli-macos-arm64.tar.gz`. Checksums and build
provenance are included with the release. The app is ad hoc signed, not Developer ID
notarized; see the [installation troubleshooting instructions](https://github.com/tomtastic/ThermalForge/blob/v13.1.0/README.md#troubleshooting)
if macOS blocks opening it.

## Verification and remaining limits

The optimized release suite passes 298 tests across 41 suites, including 16
subprocess scenarios covering failure recovery, delayed acknowledgement and service
startup. Packaging checks verify versions, extracted signatures, binary identity
and exclusion of integration fixtures. Automated tests use isolated state and
simulated hardware without replacing installed services.

Physical validation of delayed acknowledgement on the affected Mac17,7/macOS 27
machine remains outstanding. The earlier requested-versus-observed mismatch does
not prove that its firmware eventually accepts a target. Direct-mode and `Ftst`
hardware handback checks and actual GUI click automation also remain outstanding.
Permanent SMC failures or an unkillable controller leave restoration unverified
and new control blocked.

See the [flow comparison](https://github.com/tomtastic/ThermalForge/blob/v13.1.0/README.md#how-the-flow-changed-from-main)
and [test plan](https://github.com/tomtastic/ThermalForge/blob/v13.1.0/docs/control-test-plan.md)
for the architecture changes, regression evidence and remaining validation work.
